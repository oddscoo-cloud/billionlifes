# Технический план

## Стек и стоимость

TypeScript со строгой проверкой типов, Vite для сборки, HTML и CSS, DOM API для интерфейса. Node.js LTS, npm и lockfile для разработки. Vitest для тестов движка и сохранений. Playwright как инструмент проверки выпуска. В браузере нет обязательных сторонних пакетов. Портреты собираются из локальных слоёв SVG, шрифты системные.

Статическую сборку можно разместить бесплатно на GitHub Pages публичного репозитория. Vite должен корректно собирать ресурсы для пути `/billionlifes/`. Разработка и локальный запуск не требуют аккаунтов у других сервисов. Публикация — отдельное решение владельца. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## Архитектура

| Зона | Ответственность |
| --- | --- |
| `src/sim/` | Данные жизни, генератор случайных чисел с сохраняемым состоянием, месячный шаг, действия и исходы |
| `src/data/` | Версионированные снимки стран и оригинальные сценарии с устойчивыми идентификаторами |
| `src/storage/` | Схема, валидация, восстановление, чтение и атомарная запись локального снимка |
| `src/ui/` | Экран рождения, хроника, планы, выборы, связи, финальная сводка |

Одна команда интерфейса формирует неизменяемый новый снимок. Для живой сессии годовой ход прекращается при первом обязательном выборе. В сохранение входят версия схемы, версия набора данных, состояние генератора, состояние жизни и ожидающее решение. Показ вариантов и перерисовка не двигают генератор. После успешной записи интерфейс показывает результат. При ошибке записи предыдущий снимок остаётся действующим и игрок видит возможность повторить запись. Использовать транзакцию IndexedDB на чтение и запись одного снимка с проверкой ревизии, чтобы вторая вкладка не переписала более новое состояние. Старые версии мигрировать явно. Повреждённые и неизвестные версии оставить нетронутыми и показать понятный путь восстановления.

## Данные и вероятности

- Рождения и возрастная смертность по полу берутся из одного выпуска World Population Prospects ООН. Зафиксировать выпуск, год и срез. Сверять единицы, возрастные интервалы и доступность открытой возрастной группы. Для годового риска смерти q применять месячный риск `1 − (1 − q)^(1/12)` при допущении о постоянном риске внутри года. Многолетние интервалы преобразовывать сначала с учётом длины периода. Не интерпретировать ожидаемую продолжительность жизни как возраст смерти. [World Population Prospects](https://population.un.org/wpp/)
- Для достатка использовать доступные сопоставимые распределения или доли по группам дохода Всемирного банка. При нехватке данных применить явно описанное модельное приближение. Один индекс Джини не задаёт распределение. Для семьи аналогично отметить, где есть измерения, а где используются правила симуляции. [World Bank Poverty and Inequality Platform](https://pip.worldbank.org/)
- Хранить компактные снимки в репозитории вместе с источником, годом каждой метрики, единицами, лицензией, преобразованиями и командой обновления. В браузере не обращаться к внешним API. Шансы на действия показывать как оценки внутри симуляции. Привлекательность, характер и сценарии кризисов — параметры модели.

## Последовательность

| Этап | Ветка | Зависит от | Результат |
| --- | --- | --- | --- |
| 01 | `feat/01-foundation` | Документация в main | Каркас, сборка и проверки |
| 02 | `feat/02-demographics` | 01 | Шесть стран, снимки и рождение |
| 03 | `feat/03-life-engine` | 02 | Месяц, год, остановки, смерть |
| 04 | `feat/04-life-decisions` | 03 | Навыки, характер, интересы, внешность, учёба и работа |
| 05 | `feat/05-relationships` | 04 | Близкие, переломные события и кризисы |
| 06 | `feat/06-persistence` | 05 | Продолжение и устойчивые исходы |
| 07 | `feat/07-interface` | 06 | Полное веб-прохождение и финальная сводка |
| 08 | `feat/08-release-check` | 07 | Сквозные проверки, замеры и готовая статическая сборка |

Каждый этап начинает отдельная ветка от актуальной `main` после слияния предыдущего. Каждый исполнитель оставляет осмысленные коммиты и передаёт ветку на ревью. Слияние выполняется после проверки этапа, затем начинается следующий этап. Подробные задания находятся в [промптах](PROMPTS.md).

## Приёмка и производительность

- Проверить полный сценарий от рождения до смерти с фиксированным seed. Отдельно проверить младенческую смерть, паузу в середине годового хода, неудачный исход с новым доступным действием и продолжение после обновления страницы.
- Сравнить годовой ход с двенадцатью месячными при одинаковом seed и плане без обязательных выборов. Проверить остановку в одном и том же месяце при наличии выбора.
- Цели MVP для сжатых ресурсов сборки: JS и CSS на первом экране до 75 КиБ gzip суммарно, весь первый экран до 150 КиБ gzip. Отдельно считать локальные данные и портреты. Проверить p95 годового шага до 50 мс на настольном Chromium при замедлении CPU ×4, с 30 замерами после прогрева. Записать условия и результаты проверки.
- Ограничить объём отображаемой хроники последними 50 записями с подгрузкой старых. Выводить значимые события и компактные периодические записи. Измерить размер сохранения долгой жизни и проверить, что оно укладывается в 1 МиБ.
- Проверить навигацию с клавиатуры, читаемость на узком экране и запуск сборки под базовым путём проекта.
